
## gams-capi / gams-gdx

- `server/crates/gams-capi/src/loader.rs` replaces the MIT-licensed C loaders `$GAMS_SYSDIR/apifiles/C/api/{gdxcc,optcc}.c` shipped with GAMS (they are no longer compiled; `cfgmcc.c`/`palmcc.c` were never used). The Rust code (`libloading`) reproduces their behavior as read from those files: library name `lib<gdxcclib|optdclib>64.so` / `<..>64.dll` / `lib<..>64.dylib` (GMS_DLL_PREFIX/BASENAME/SUFFIX/EXTENSION) joined to the sysdir, no other search order; symbol lookup lower/original/upper case; `XCreate`/`XFree`/`XCheck`/`XAPIVersion` (gdx: `C__XCheck`, `C__XAPIVersion`, API 11, plus `XCreateD`; opt: `CXCheck`, `CXAPIVersion`, API 4), `XCheck(name,nargs,signature)` per function with the signature codes and `C__`/`C`/`` symbol prefixes from the `CheckAndLoad` lines, optional `*SetLoadPath(sysdir)`, first successful load wins, object refcount blocks unload. Error text: `Could not load shared library <path>: <os error>`, `Could not load symbol '<sym>': <os error>`. Nothing from GAMS is needed at build time.
- FFI signatures in `src/gdx.rs` / `src/opt.rs` hand-written from `$GAMS_SYSDIR/apifiles/C/api/gdxcc.h`, `optcc.h`, `gclgms.h` (GMS_SSSIZE=256, GMS_MAX_INDEX_DIM=20, GMS_UEL_IDENT_SIZE=64, GMS_SV_* special values, GMS_DT_*, `gmsFixEquType`/`gmsFixVarType`). API functions are global function-pointer tables (`GDX_FUNCPTR` in C), `None` until `gdx::create`/`opt::create` succeeds.
- `gams-gdx` reads GDX files with `gdx-rs` (section below); the previous C API backend is kept as `gams_gdx::capi` behind the feature `capi-oracle` for tests. Call sequence ported from Studio `src/gdxviewer/gdxviewer.cpp` (gdxSetExitIndicator(0), gdxSetScreenIndicator(0), gdxCreateD, gdxOpenRead, gdxErrorStr), `gdxsymboltablemodel.cpp` (gdxSystemInfo, gdxUMUelGet, gdxUMFindUEL, gdxGetElemText; element text nr<=0 is "Y"), `gdxsymbol.cpp` (gdxSymbolInfo, gdxSymbolInfoX, gdxSymbolGetDomainX, gdxDataReadRawStart/Raw/Done; special-value decoding in `formatValue`: UNDF/NA/+INF/-INF/EPS, >= GMS_SV_ACR acronym via gdxAcronymName).
- `gams-capi::optdef` ported from Studio `src/option/option.cpp` (`Option::readDefinition`: optCreateD, optReadDefinition, optCount, optGetHelpNr, optGetInfoNr, optGetOptHelpNr, optIsDeprecated).
- Test fixtures `crates/gams-gdx/tests/fixtures/*.gdx` are self-written (`mini.gdx`: GAMS 54.6.1 output of the self-written `mini.gms`; the others from the pure Rust writer, `examples/write_fixtures.rs`); expected values cross-checked with `$GAMS_SYSDIR/gdxdump` (runs without license). Nothing is copied from `$GAMS_SYSDIR`; tests that need sysdir samples read them at runtime.
- GDX file handles: Studio releases a GDX file before a run so GAMS can rewrite it (`GdxViewer::releaseFile`, `src/gdxviewer/gdxviewer.cpp`); `gams/gdxRelease` is the equivalent (project design, cited in review, not re-checked against $STUDIO_SRC here). Set records without element text show "Y" (`gdxsymboltablemodel.cpp`, same citation). Loader constraints from `$GAMS_SYSDIR/apifiles/C/api/{gdxcc,optcc}.c`: the C `libloader` copied the sysdir into `char[512]` (strncpy + strcat + strncat); the Rust loader keeps the historical limit (sysdirs >= 480 bytes are rejected with the same error). Loading/creating/freeing is serialised by mutexes in `loader.rs`.

Deviations / simplifications (also commented in code):
- Studio keeps the eol-comment setup in highlighter-global mutable objects (`SharedSyntaxData`); here it is part of `LineState`, so results are deterministic for a top-down pass.
- The syntax stack is stored by value in `LineState` instead of an index into a global `CodeRelation` list (same semantics, incl. "shift on the root keeps the root as parent").
- The DCO regex is evaluated once per line (all match positions precomputed) instead of re-running it per candidate; results are identical.
- Declaration flavors are keyed by sorted dictionary position (Studio keys by unsorted index but looks up by sorted index; identical for current data). Stable sort instead of `std::sort` (no duplicate keys).
- Keyword docs (`docForLastRequest`) are attached to the winning block only (Studio reads the last `findEnd` index of the syntax object); docs are also returned for post-highlighted `%...%` attributes.
- `QChar` predicates are approximated by Rust `char` predicates (exact for ASCII). `SyntaxQuoted` with flavor&3==3 would index past its delimiter string in Studio; here it never matches. A non-progress guard ends a line instead of looping. Studio's max-line-length/max-block-count limits are not ported.
- Studio quirks preserved: `$title`/`$hidden` bodies render as `DcoBody` (the DcoBody sub-kind wins), `!!` after code is only a comment once `$onEolCom`/`$eolCom` was seen, `=e=` only becomes `Assignment` after `$onEolCom`/`$eolCom`, `CommentInline` has no registered syntax (inline comments are never highlighted), DCOs are only recognized in column 1 or as `$$`.

Python` and `source.yaml` for `... Connect` embedded code blocks.
- DEVIATION (brackets): Studio drops the rest of a line after `abort`/`execute`/`executeTool` when no syntax matches (e.g. `abort$(a>1 and`, `execute$(x) 'ls';);`) and after a data value followed by `)` (`'z.gdx') "text")` in `apilib_ml/gdxperf.gms`); the port keeps the syntax kinds, but lists the `( [ {` / `) ] }` of that dropped rest in `Nesting::parentheses` like code (quoted texts skipped, an active eol comment ends the scan). Studio only shows a mismatch at the cursor, our nesting colors are always visible. Brackets inside embedded code (`M`/`E` markers) are never reported invalid (foreign syntax). Corpus check: `gams-lsp` `parens::corpus` (no invalid bracket in the `*_ml` models except `embed1` (compile error on purpose) and `decis03` (closes blocks after `$goTo`/`$exit`), no listed bracket in a comment, string, description, title or DCO body).
- DEVIATION (end-of-line comments): once `$onEolCom`/`$eolCom` is active, an end-of-line comment that follows only blanks wins over a block that starts with those blanks. Studio picks the block with the smaller start, so with `$eolCom //` it reads `Parameter p(i) // text (x)` as an empty data block `/ /` followed by code (colors and brackets of the comment shown as code); GAMS reads a comment. `highlighter.rs` (block selection), tests `end_of_line_comment_after_declaration` and `parens::studio_list_excludes_custom_eol_comment`.
- DEVIATION (semantic tokens): `EmbeddedBody` gets no semantic token (Studio paints it with the embedded slot) so the TextMate embedding (Python, Connect YAML) stays visible.
- Incremental re-highlighting (`rehighlight`, `rehighlight_change`): like `QSyntaxHighlighter`, lines are re-highlighted from the first changed one until a line starts in the same state as before (`LineState` equality); identical to a full pass (tests `gams-syntax/tests/incremental.rs`, `gams-lsp/tests/keystroke.rs`). Semantic tokens support `full/delta` (one prefix/suffix edit).
- Outline (`outline.rs`, own design): `Alias (i,ii),(j,jj);` declares the names of each group except the one known before (`UG_SetDefinition.html` "The Alias Statement": exactly one name of the statement is defined earlier; without a known one all but the first); declarations in the new input line of `$if`/`$ifI`/`$ifE` after the conditional expression (expression forms from `UG_DollarControlOptions.html` "Conditional Expressions in Conditional Compilation"); a re-declared symbol (`Variable x; Positive Variable x;`) is listed once; a framed header `*---- Name ----` has the name without the leading dashes.
